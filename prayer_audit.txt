# Prayer Time Calculation, Time Zones, and Location Defaults

This document records the prayer-time accuracy audit, the calculation convention
used by the app, the time-zone rules, the default/upgrade behavior for locations,
and the reference comparison that was performed.

---

## 1. Calculation convention

The app uses one named convention, `PrayerCalculationMethod.TUNISIA`:

| Parameter | Value |
| --- | --- |
| Fajr angle | 18.0° below the horizon |
| Isha angle | 18.0° below the horizon |
| Asr | Standard shadow factor (`Madhab.SHAFI`, also used by the Maliki convention) |
| High-latitude rule | None (Tunisia is far from the polar circles) |
| Calculation library | Batoul Apps Adhan 1.2.1 (Jean Meeus algorithms) |

This preserves the convention that was already configured before the audit. It is
a named implementation convention, not a claim that it is the only timetable used
in Tunisia. The convention is displayed on the Settings screen so it is explicit
to the user.

The engine exposes six astronomical events. Sunrise is returned as
`CalculatedTimetable.sunrise`; it is not one of the five obligatory prayers, so it
is not added to `PrayerType` or to the alarm rows.

---

## 2. Time-zone and date handling

### Conversion path

Adhan returns `java.util.Date` values that represent UTC instants. The app converts
each one exactly once:

```kotlin
dateObj.toInstant().atZone(locationZoneId)
```

The app does **not** reinterpret a wall-clock value as UTC and does **not** apply a
hardcoded minute offset.

- The location's stored IANA zone (for example `Africa/Tunis`) is the only zone
  used for its timetable.
- The current local date is obtained with `LocalDate.now(clock.withZone(zoneId))`.
- Countdowns compare `Instant` values, so the device's default zone cannot shift a
  prayer by an hour.
- An invalid persisted zone falls back to `Africa/Tunis`; valid user input is
  rejected by `LocationValidator` before it is saved.

### Daylight saving time

`java.time.ZoneId` supplies the historical and future offset rules for each IANA
zone. No fixed UTC offset is stored. A regression test uses `Europe/Paris` across
the 2026-03-29 DST transition and verifies that the calculated Fajr offset changes
from `+01:00` to `+02:00`. Tunisia itself has not observed DST since 2009, but the
same code path supports locations that do.

### Date boundaries

Tests cover:

- the last day of a month → first day of the next month;
- 2026-12-31 → 2027-01-01;
- the post-Isha rollover to tomorrow's Fajr;
- prayer selection exactly at a prayer timestamp (the next prayer is selected).

After Isha, tomorrow's Fajr is shown in the next-prayer card/notification. The
rows in today's timetable are left untouched and no row is marked "next", so
today's Fajr time is never overwritten with tomorrow's time.

---

## 3. Default locations, seeding, and upgrades

A fresh install is seeded with exactly these three rows, in this order:

| Order | Name | Latitude | Longitude | IANA zone |
| --- | --- | --- | --- | --- |
| 1 | Mahdia | 35.5047 | 11.0622 | Africa/Tunis |
| 2 | Ariana | 36.8625 | 10.1956 | Africa/Tunis |
| 3 | Kelibia | 36.8476 | 11.0939 | Africa/Tunis |

Mahdia is selected after a fresh seed.

`LocationSeeder` runs at application startup and is intentionally conservative:

1. It inserts the defaults **only** when the location table is empty.
2. It never deletes, updates, or re-inserts existing rows.
3. It preserves a valid existing selection.
4. It repairs only an unset selection or a selection pointing at a deleted row.
5. A mutex prevents two concurrent startup passes from double-seeding.

The existing `MIGRATION_1_2` behavior is retained: on upgrade it inserts a default
row only when an exact identity match (name, latitude, longitude, time zone) does
not already exist. It does not delete or overwrite user data. Custom locations and
the user's selected location therefore survive an upgrade.

Users can add locations manually with a name, latitude, longitude, and IANA zone.
Coordinates must be finite and within ±90°/±180°. Offset-style zone IDs such as
`+01:00` or `Z` are rejected because they have no historical DST rules; only IANA
zone IDs known to `java.time` are accepted.

---

## 4. Reference comparison

### Reference source

The independent reference is the Aladhan API v1 `timings` endpoint using method
18 (labelled "Tunisia") and `school=0` (standard Asr):

```text
https://api.aladhan.com/v1/timings/DD-MM-YYYY?latitude=...&longitude=...&method=18&school=0
```

Reference values were captured during this audit and rounded to the nearest minute.
They are compared with the app's Adhan output for the same coordinates and dates.
This is a cross-check against a widely used published API, not a claim of exact
equivalence with an official Tunisian government timetable.

### Non-Asr events

The app's underlying values may include seconds; the table shows whole minutes.

### Known limitations

- **Not an official timetable:** the app does not claim exact equivalence with any
  government-published Tunisian timetable. Official tables may use different
  rounding, safety margins, or a different Asr convention.
- **No elevation correction:** coordinates are used at sea level. Elevation can
  shift sunrise/sunset slightly at high altitude.
- **No high-latitude fallback rule:** this is acceptable for Tunisia but would
  need a policy for polar locations.
- **No geocoding:** locations are entered manually; there is no provider/API key.
- **Minute display:** the UI displays `HH:mm`; seconds are retained internally for
  countdowns but not shown in the timetable.
- **Asr convention:** the standard shadow factor is used. A Hanafi user would see
  a later Asr, and that choice is not currently user-configurable.

---

## 5. Countdown timing

The countdown uses prayer timestamps as the source of truth:

1. Prayer times are full `ZonedDateTime` values in the location's IANA zone.
2. Remaining time is `Duration.between(now, targetInstant)`.
3. The one-second ticker re-reads the real clock instead of decrementing counters,
   so scheduling latency does not accumulate as drift.
4. The current and following local day are cached; the ticker only recomputes when
   the local date changes.
5. After Isha the target is tomorrow's Fajr, with tomorrow's time shown in the
   next-prayer card and notification.

---

Relevant tests:

- `PrayerTimeCalculatorTest`: all six events, reference comparison, chronological

- `LocationSeederTest`: fresh seeding, idempotence, upgrade preservation, unset and
  dangling selection repair.
- `LocationRepositoryImplTest`: persistence, location switching, duplicate

- `LocationValidatorTest`: coordinate bounds, non-finite values, IANA zones, and

# Alarms and Notifications: Native Android Execution

The core value proposition of Prayer Alarm is its deterministic waking alarm around Fajr and its persistent next-prayer countdown. On modern Android, background reliability requires strict adherence to system constraints.

---

## 1. The Alarm System Architecture

```
                               ┌────────────────────────┐
                               │   AlarmPlanGenerator   │
                               │  (Computes Schedules)  │
                               └───────────┬────────────┘
                                           │ List<PlannedAlarm>
                                           ▼
                               ┌────────────────────────┐
                               │   AlarmScheduler API   │
                               └───────────┬────────────┘
                                           │
                ┌──────────────────────────┴──────────────────────────┐
                ▼                                                     ▼
┌───────────────────────────────┐                     ┌───────────────────────────────┐
│     NativeAlarmScheduler      │                     │   SystemClockAlarmScheduler   │
│  (Hardware RTC Exact Alarms)  │                     │   (AlarmClock.ACTION_SET)     │
└───────────────┬───────────────┘                     └───────────────────────────────┘
                │ AlarmManager.setExactAndAllowWhileIdle
                ▼
┌───────────────────────────────┐
│      Android AlarmManager     │
└───────────────┬───────────────┘
                │ Triggers PendingIntent
                ▼
┌───────────────────────────────┐
│      PrayerAlarmReceiver      │
└───────────────┬───────────────┘
                │ Displays
                ▼
┌───────────────────────────────┐
│   Alarm Ringing UI / Audio    │
└───────────────────────────────┘
```

---

## 2. Why `AlarmManager` with `setExactAndAllowWhileIdle()`?

Android offers several scheduling mechanisms:
- `WorkManager`: Designed for deferrable background jobs (syncing files, sending logs). Batched by Doze Mode; can be delayed by 10 to 45 minutes. **Unusable for prayer alarms.**
- `AlarmManager.setInexactRepeating()`: Batched by OS to conserve battery. Times can drift significantly.
- **`AlarmManager.setExactAndAllowWhileIdle()`**: Specifically intended for alarms and calendar events that must trigger at a precise millisecond, even if the device is in deep Doze mode.

---

## 3. Permissions for Exact Alarms (Android 12+)

- **`android.permission.SCHEDULE_EXACT_ALARM`**: Declared in `AndroidManifest.xml`.
- Starting on Android 13/14, users or battery management tools can revoke exact alarm access in App Info.
- **Defensive API Check**:
  ```kotlin

  if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
      if (!alarmManager.canScheduleExactAlarms()) {

      }
  ```

## 4. Boot Recovery (`RECEIVE_BOOT_COMPLETED`)

When an Android phone turns off or restarts, **all scheduled alarms in `AlarmManager` are cleared by the Linux kernel.**

To ensure the user never misses Fajr after a reboot:
1. We declare `RECEIVE_BOOT_COMPLETED` permission.
2. We register `BootReceiver : BroadcastReceiver` in the manifest.
3. When the device finishes booting, the OS broadcasts `android.intent.action.BOOT_COMPLETED`.
4. Our `BootReceiver` runs, reads active alarm plans from the Room database, recomputes the next Fajr, and reschedules the exact hardware alarms immediately.

## 5. Notification Channels (Android 8.0+ / API 26+)

All notifications on modern Android must belong to a channel:
1. **`prayer_countdown_channel`**: Low importance, silent, no vibration. Displays the ongoing countdown to the next prayer.
2. **`prayer_arrival_channel`**: High importance, sound and vibration enabled. Notifies the user when a prayer time arrives.
3. **`fajr_alarm_channel`**: Max importance, loud audio, bypasses DND where permitted.

## 6. Persistent countdown lifecycle

The next-prayer notification is maintained by
`CountdownNotificationService`, a foreground service declared with
`stopWithTask="false"`. The service recalculates the target prayer from the
selected location's timezone and the current system `Instant` every second; it
does not decrement a counter owned by a screen or `ViewModel`. This keeps the
notification current when the activity is recreated, the screen is locked, or
the activity task is removed from Recents. The stable notification ID and
existing countdown channel are reused, so updates replace rather than
duplicate the notification.

The collapsed and expanded notification use the platform text layout with the
prayer name as the title and a compact `countdown    scheduled time` content
line. Android may truncate or reflow that line depending on the device's
system notification template. The service still requires a visible foreground
notification and `POST_NOTIFICATIONS` where applicable; force-stop and
manufacturer-specific battery restrictions remain platform limitations.

## Alarm plan generation

The pure `AlarmPlanGenerator` creates a deterministic list of `LocalDateTime`
values from a Fajr timestamp and an `AlarmPlanConfig`. The alarm count is the
total number of alarms, including Fajr when the generated schedule reaches it.

- `BEFORE_FAJR`: alarms are spaced backwards and the final alarm is at Fajr.
- `AT_OR_AFTER_FAJR`: the first alarm is at Fajr and later alarms are after it.
- `BOTH`: currently means the combined pre-Fajr sequence ending at Fajr. This
  matches the product example of five alarms at 04:20, 04:30, 04:40, 04:50,
  and 05:00 for a 05:00 Fajr. It does not silently create more than the
  configured count.

The generator is independent of Android scheduling APIs, so invalid counts,
intervals, disabled plans, duplicate timestamps, and midnight date changes can
be tested using fixed values before any `AlarmManager` integration is added.

## Native scheduling boundary

`AndroidAlarmScheduler` is the Android boundary for a tested alarm plan. Each
request carries an explicit non-negative `requestCode`, trigger timestamp,
prayer name, and location name. The request code is used as the
`PendingIntent` identity so different alarms do not overwrite each other.
Scheduling uses `setExactAndAllowWhileIdle` only when Android reports exact
alarm access; otherwise it returns `ExactAlarmPermissionRequired` for the UI to
explain and remediate.

`PrayerAlarmReceiver` posts a high-importance notification and exits when
`POST_NOTIFICATIONS` is denied. Notification channels are created from the
Application and defensively by the receiver. This checkpoint does not yet
persist alarm plans, expose alarm settings, reconcile obsolete schedules, or
reschedule after reboot; those require the settings and persistence layers.

The Alarms destination now exposes a Compose preview backed by the live Fajr
time from `HomeUiState`. It validates count and interval through the same pure
generator used by scheduling.

Alarm settings are now persisted through `UserPreferencesManager`. Defaults are
five alarms, ten-minute intervals, combined pre-Fajr mode, and disabled plan.
`AlarmPlanViewModel` exposes the settings as a `StateFlow`, reports DataStore
errors to the UI, and rejects non-positive count or interval values before
writing. The current checkpoint persists settings but does not yet reconcile
them with `AlarmManager`.

`PrayerAlarmCoordinator` is the reconciliation boundary for the next
integration step. It converts one or more timezone-aware Fajr timestamps into
future `ScheduledPrayerAlarm` values, cancels obsolete request codes, and
delegates scheduling to a fakeable `PrayerAlarmScheduler`. The current
coordinator is covered independently and is now observed by an application
ViewModel. Changes to the active location or persisted alarm settings trigger
reconciliation for today and tomorrow. The in-memory identity list is bounded
to that rolling horizon; durable identity storage remains future work.

`PrayerAlarmRecoveryReceiver` invokes the same bounded today/tomorrow
reconciliation after boot, date changes, manual time changes, timezone changes,
and package replacement. It uses `goAsync()` so Room/DataStore reads and
astronomical calculation run off the receiver callback. Recovery reconstructs
the bounded request-code set so a disabled plan can cancel alarms from the
previous horizon. Manufacturer battery restrictions and physical delivery
still require device verification.

The Settings destination exposes exact-alarm and notification permission status
with links to the relevant Android system settings pages. It does not claim
that a permission grant guarantees delivery on every manufacturer image.

# Data and Persistence: Room & DataStore

Prayer Alarm is designed to work 100% offline without GPS or cloud accounts. This makes robust local device persistence essential.

## 1. Storage Architecture Overview

The application utilizes two distinct persistence mechanisms:

## 2. Room SQLite Architecture

### Core Concepts Explained

#### SQLite
SQLite is an embedded, serverless, self-contained SQL database engine compiled directly into the Android operating system. Unlike client-server databases (e.g., PostgreSQL, MySQL), SQLite reads and writes directly to regular disk files stored in the app's private sandbox (`/data/data/com.example.prayeralarm/databases/`).

#### Room Persistence Library
Room is Google's official object-mapping abstraction layer over SQLite. It provides:
- Compile-time verification of raw SQL queries (using KSP).
- Elimination of boilerplate `Cursor` and `ContentValues` code.
- Native integration with Kotlin coroutines (`suspend`) and asynchronous streams (`Flow`).

#### Primary Components:

1. **Entity (`@Entity`)**:
   Represents a database table. In our app: `com.example.prayeralarm.data.local.entity.LocationEntity`:
   ```kotlin
   @Entity(tableName = "saved_locations")
   data class LocationEntity(
       @PrimaryKey(autoGenerate = true)
       val id: Long = 0L,
       @ColumnInfo(name = "name")
       val name: String,
       @ColumnInfo(name = "latitude")
       val latitude: Double,
       @ColumnInfo(name = "longitude")
       val longitude: Double,
       @ColumnInfo(name = "timezone_id")
       val timeZoneId: String
   )
   ```

2. **Primary Key (`@PrimaryKey(autoGenerate = true)`)**:
   A column or set of columns uniquely identifying each row in the table. Setting `autoGenerate = true` allows SQLite to assign an incrementing 64-bit integer automatically.

3. **Data Access Object (`@Dao`)**:
   The interface defining data interaction contracts (`com.example.prayeralarm.data.local.dao.LocationDao`). Room generates the concrete implementation at compile time:
   - **`suspend` functions**: Used for one-shot insert, update, and delete mutations. Executed off the main thread.
   - **`Flow<T>` queries**: Used for observable reads. Emits an updated list whenever the underlying table records are modified.

4. **Database (`@Database`)**:
   Abstract class extending `RoomDatabase` (`com.example.prayeralarm.data.local.PrayerAlarmDatabase`). Annotations define entity lists and versioning. Also handles database pre-population using `RoomDatabase.Callback`.

---

## 3. DataStore Preferences for Active Location Selection

### Why Not Store Active Selection in the Room Location Row?
If we stored an `is_active` boolean column directly in the `saved_locations` SQLite table:
1. Selecting a new active location would require a two-step transactional write: setting `is_active = 0` for all rows, then `is_active = 1` for the target row.
2. It mixes persistent city catalog metadata with dynamic user application state.
3. Decoupling the active selection to **Jetpack DataStore Preferences** (`UserPreferencesManager`) allows atomic updates via a single key (`selected_location_id: Long`), ensuring instant response and zero table locking.

---

The `LocationRepository` interface acts as the single source of truth for the rest of the application:

## 7. Default locations and migration

Fresh installations seed three benchmark locations: Mahdia, Kelibia, and Ariana.
Mahdia is selected only when the database starts empty. Existing user locations
and the existing DataStore selection are preserved.

Room database version 2 includes an explicit `MIGRATION_1_2`. It inserts each
preferred location only when the exact name, coordinates, and IANA timezone are
not already present. The migration does not delete rows and does not overwrite
`selected_location_id`, so upgrading an existing installation cannot silently
change the user's active city.

The migration uses `INSERT ... SELECT ... WHERE NOT EXISTS` because the original
schema has no uniqueness constraint for location identity. Future schema changes
should consider a deliberate identity constraint or a dedicated stable seed key.

The repository also checks this identity before inserting a user location. If an
exact duplicate is submitted, the existing row is reused. Deleting the active
location selects the first remaining saved location, or clears the DataStore
selection when the database becomes empty. This keeps the Home screen's active
location flow valid after destructive actions.

Alarm-plan preferences are stored in the same DataStore file using stable keys
for enabled state, count, interval, and timing mode. The alarm ViewModel owns
the authoritative `StateFlow<AlarmPlanConfig>` and persists only positive
count/interval values. The Compose screen renders that flow and sends actions
back to the ViewModel rather than keeping the durable settings in `remember`
state.

# Engineering Decisions & Tradeoffs

Every architecture involves tradeoffs. This document records critical design choices made in Prayer Alarm, the alternatives considered, and the technical justification.

---

## 1. No GPS Permission vs. Automatic Geolocation

- **Decision**: Zero GPS permission. Manual coordinate entry and preloaded Tunisian city catalog.
- **Alternatives Considered**: Using Google Play Services `FusedLocationProviderClient` to detect user coordinates automatically.
- **Reasoning**:
  - *Battery Life*: Continuous location tracking drains battery unnecessarily.
  - *Privacy*: Users should not have to share their physical coordinates with any app to know when to pray.
  - *Determinism*: Cities do not move. Selecting a city once from a list is completely reliable and works indoors or in airplane mode.
- **Tradeoff**: When traveling to a new city, the user must select it manually.

---

## 2. On-Device Astronomical Math vs. Cloud Prayer APIs (e.g. Aladhan API)

- **Decision**: 100% on-device astronomical calculation.
- **Alternatives Considered**: Fetching daily timings from REST APIs.
- **Reasoning**:
  - Cloud APIs introduce network latency, require internet access, can suffer outages, and can change their backend algorithms without notice.
  - An alarm must wake the user up even if their phone has no internet connection or is in flight mode during the night.
- **Tradeoff**: We must implement, verify, and unit-test the spherical trigonometry algorithms directly in Kotlin.

---

## 3. Jetpack Compose vs. Legacy XML Views

- **Decision**: 100% Jetpack Compose with Material 3.
- **Alternatives Considered**: XML layouts with `ConstraintLayout`, `RecyclerView`, and `ViewBinding`.
- **Reasoning**:
  - Compose is Google's modern, recommended declarative framework.
  - Far fewer lines of code, seamless dynamic theme switching, eliminates view-binding boilerplate, and provides first-class state observation with Kotlin `StateFlow`.
- **Tradeoff**: Requires team familiarity with declarative UI and recomposition lifecycle.

---

## 4. Native `AlarmManager` vs. Android `WorkManager` for Wakeups

- **Decision**: Use `AlarmManager.setExactAndAllowWhileIdle()` for waking alarms.
- **Alternatives Considered**: `WorkManager.enqueueUniquePeriodicWork()`.
- **Reasoning**:
  - Google's official documentation explicitly specifies that `WorkManager` is for deferrable background jobs. In deep Doze mode, periodic workers are batched and delayed by up to 30+ minutes.
  - A Fajr alarm scheduled for 05:10 must not ring at 05:42.
- **Tradeoff**: Requires exact alarm permissions and explicit handling of phone reboots via `RECEIVE_BOOT_COMPLETED`.

---

## 6. Location Search & Geocoding (Phase 3)

### 6.1 Geocoding provider: OpenStreetMap Nominatim

- **Decision**: Use OpenStreetMap's Nominatim service for city search (query → coordinates + place details).
- **Official policy consulted**: https://operations.osmfoundation.org/policies/nominatim/ (Nominatim Usage Policy / Geocoding Policy).
- **Why it was selected**:
  - Free to use, no paid plan, no mandatory API key, no account, no backend.
  - Permits end-user-triggered search from a mobile app for a moderate number of users.
  - Returns coordinates (latitude/longitude) plus address components (city, admin area, country) needed to distinguish similarly named places.
- **Usage restrictions that the implementation must respect**:
  - Absolute maximum of **1 request per second** (per application, summed across all users).
  - A **custom HTTP User-Agent** identifying the application must be sent (stock HTTP library user-agents are rejected).
  - **Attribution** must be displayed (data is under the ODbL license).
  - **Autocomplete / per-keystroke search is strictly forbidden** — searches must be explicit (search action) and debounced; never one request per keystroke.
  - Requests must be user-triggered, not automatic polling.
  - Results must be cached on the client; the app must be able to switch providers without a software update.
  - No personal data beyond the location query is sent.
- **Privacy**: Only the city/search query is sent to Nominatim. No GPS, no device identifiers, no user account information.

### 6.2 Timezone resolution

- **Decision**: Resolve the IANA timezone ID offline using `us.dustinj.timezonemap:timezonemap:4.5` (Maven Central), with a **manual IANA timezone picker** as fallback when resolution returns no result.
- **Why it was selected**:
  - Free, no API key, no account, no backend, works offline.
  - Returns canonical IANA identifiers (e.g., `Europe/London`, `America/New_York`, `Africa/Tunis`) derived from OpenStreetMap time-zone boundaries.
  - Android SDK 19+ compatible.
- **Known limitations (documented)**:
  - The library's latest release (4.5) dates from 2021 and is no longer actively maintained; it is treated as a non-critical, replaceable component.
  - It initializes per bounding-box region; the app initializes it with world bounds so any searched city can be resolved.
  - It adds transitive dependencies (Esri geometry API, Apache Commons Compress) and an optional native zstd component.
- **Fallback behavior**: If a searched location's timezone cannot be resolved (ocean, unindexed, or library failure), the result is **rejected**. The user is shown an error and offered a manual picker populated from `java.time.ZoneId.getAvailableZoneIds()`. The location is **never** silently saved with `Africa/Tunis` or any guessed timezone.
- **Alternatives considered and rejected**:
  - Free web timezone-by-coordinates services (e.g., TimeZoneDB, GeoNames): require a mandatory API key / account, violating the "no mandatory API key" rule.
  - Android's location time-zone detection: resolves only the device's own location, not an arbitrary searched city.
  - Deriving a timezone from longitude alone: inaccurate (ignores time-zone boundaries and daylight-saving rules); explicitly prohibited.

### 6.3 Duplicate-location identity

- **Decision**: Duplicate detection uses normalized name + latitude + longitude + timeZoneId (exact match on all four), reusing the existing row when an equivalent saved location already exists. Distinct coordinates or timezones are treated as different locations, so legitimately similar places (e.g., same city name in different countries) are not merged.

package com.example.prayeralarm.alarm

import android.app.AlarmManager
import android.app.PendingIntent
import android.content.Context
import android.content.Intent
import android.os.Build

data class ScheduledPrayerAlarm(
    val requestCode: Int,
    val triggerAtMillis: Long,
    val prayerName: String,
    val locationName: String
)

sealed interface AlarmScheduleResult {
    data object Scheduled : AlarmScheduleResult
    data object Cancelled : AlarmScheduleResult
    data object ExactAlarmPermissionRequired : AlarmScheduleResult
    data class Invalid(val message: String) : AlarmScheduleResult
}

interface PrayerAlarmScheduler {
    fun schedule(alarms: List<ScheduledPrayerAlarm>): AlarmScheduleResult
    fun cancel(alarms: List<ScheduledPrayerAlarm>): AlarmScheduleResult
}

class AndroidAlarmScheduler(context: Context) : PrayerAlarmScheduler {

    private val applicationContext = context.applicationContext
    private val alarmManager =
        applicationContext.getSystemService(Context.ALARM_SERVICE) as AlarmManager

    override fun schedule(alarms: List<ScheduledPrayerAlarm>): AlarmScheduleResult {
        if (alarms.any { it.triggerAtMillis <= 0L || it.requestCode < 0 }) {
            return AlarmScheduleResult.Invalid("Alarm identity and trigger time must be positive.")
        }
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S &&
            !alarmManager.canScheduleExactAlarms()
        ) {
            return AlarmScheduleResult.ExactAlarmPermissionRequired
        }

        return try {
            alarms.forEach { alarm ->
                alarmManager.setExactAndAllowWhileIdle(
                    AlarmManager.RTC_WAKEUP,
                    alarm.triggerAtMillis,
                    pendingIntent(alarm)
                )
            }
            AlarmScheduleResult.Scheduled
        } catch (securityException: SecurityException) {
            AlarmScheduleResult.Invalid(
                securityException.message ?: "Android rejected exact alarm scheduling."
            )
        }
    }

    override fun cancel(alarms: List<ScheduledPrayerAlarm>): AlarmScheduleResult {
        alarms.forEach { alarm ->
            alarmManager.cancel(pendingIntent(alarm))
        }
        return AlarmScheduleResult.Cancelled
    }

    private fun pendingIntent(alarm: ScheduledPrayerAlarm): PendingIntent {
        val intent = Intent(applicationContext, PrayerAlarmReceiver::class.java).apply {
            putExtra(PrayerAlarmReceiver.EXTRA_PRAYER_NAME, alarm.prayerName)
            putExtra(PrayerAlarmReceiver.EXTRA_LOCATION_NAME, alarm.locationName)
        }
        return PendingIntent.getBroadcast(
            applicationContext,
            alarm.requestCode,
            intent,
            PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE
        )
    }
}

            while (isActive) {
                val config = application.alarmPlanPreferences.config.first()
                if (!config.enabled) {
                    stopSelf()
                    return@launch
                }
                val location = application.locationRepository.getActiveLocation().first()
                if (location == null) {
                    NotificationHelper.cancel(this@CountdownNotificationService)
                    delay(1000L)
                    continue
                }

                val zone = PrayerTimeCalculator.zoneIdFor(location)
                val currentDate = LocalDate.now(clock.withZone(zone))
                if (cachedLocationId != location.id || cachedDate != currentDate) {
                    cachedLocationId = location.id
                    cachedDate = currentDate
                    today = PrayerTimeCalculator.calculateTimetable(location, currentDate)
                    tomorrow = PrayerTimeCalculator.calculateTimetable(location, currentDate.plusDays(1))
                }

                val now = Instant.now(clock)
                val countdown = PrayerTimeCalculator.computeNextPrayerAndCountdown(
                    location = location,
                    currentDate = currentDate,
                    now = now,
                    todayTimetable = checkNotNull(today),
                    tomorrowTimetable = tomorrow
                )
                val nextPrayer = countdown.nextPrayerItem
                val target = countdown.nextPrayerDateTime
                if (nextPrayer != null && target != null) {
                    NotificationHelper.updateCountdown(
                        context = this@CountdownNotificationService,
                        nextPrayer = nextPrayer,
                        remainingMillis = java.time.Duration.between(now, target).toMillis(),
                        selectedLocation = location
                    )
                }
                delay(1000L)
            }
        }
    }

    override fun onTaskRemoved(rootIntent: Intent?) {
        // Removing the activity task must not stop this foreground service.
        super.onTaskRemoved(rootIntent)
    }

    override fun onDestroy() {
        updateJob?.cancel()
        serviceScope.cancel()
        super.onDestroy()
    }

    override fun onBind(intent: Intent?): IBinder? = null

    companion object {
        private const val ACTION_STOP = "com.example.prayeralarm.action.STOP_COUNTDOWN"

        fun start(context: Context) {
            if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU &&

        }

package com.example.prayeralarm.alarm

import com.example.prayeralarm.domain.alarm.AlarmPlanConfig
import com.example.prayeralarm.domain.alarm.AlarmPlanGenerator
import java.time.Instant
import java.time.ZonedDateTime

data class FajrScheduleDay(
    val fajrAt: ZonedDateTime
)

sealed interface AlarmReconciliationResult {
    data class Applied(
        val desired: List<ScheduledPrayerAlarm>,
        val cancelled: List<ScheduledPrayerAlarm>
    ) : AlarmReconciliationResult

    data class Failed(val reason: AlarmScheduleResult) : AlarmReconciliationResult
}

class PrayerAlarmCoordinator(
    private val scheduler: PrayerAlarmScheduler
) {
    fun requestCodeFor(day: FajrScheduleDay, sequence: Int): Int {
        return stableRequestCode(day.fajrAt, sequence)
    }

    fun reconcile(
        days: List<FajrScheduleDay>,
        config: AlarmPlanConfig,
        now: Instant,
        existing: List<ScheduledPrayerAlarm>
    ): AlarmReconciliationResult {
        val desired = if (config.enabled) {
            days.flatMap { day ->
                when (val result = AlarmPlanGenerator.generate(
                    day.fajrAt.toLocalDateTime(),
                    config
                )) {
                    is com.example.prayeralarm.domain.alarm.AlarmPlanResult.Success -> {
                        result.alarms.mapNotNull { alarm ->
                            val instant = alarm.scheduledAt.atZone(day.fajrAt.zone).toInstant()
                            if (!instant.isAfter(now)) {
                                null
                            } else {
                                ScheduledPrayerAlarm(
                                    requestCode = stableRequestCode(day.fajrAt, alarm.sequence),
                                    triggerAtMillis = instant.toEpochMilli(),
                                    prayerName = "Fajr",
                                    locationName = "Selected location"
                                )
                            }
                        }
                    }

                    is com.example.prayeralarm.domain.alarm.AlarmPlanResult.Invalid -> {
                        return AlarmReconciliationResult.Failed(
                            AlarmScheduleResult.Invalid(result.message)
                        )
                    }
                }
            }.distinctBy { it.requestCode }
        } else {
            emptyList()
        }

        val desiredIds = desired.map { it.requestCode }.toSet()
        val obsolete = existing.filter { it.requestCode !in desiredIds }
        val cancelResult = scheduler.cancel(obsolete)
        if (cancelResult !is AlarmScheduleResult.Cancelled) {
            return AlarmReconciliationResult.Failed(cancelResult)
        }

        val scheduleResult = scheduler.schedule(desired)
        if (scheduleResult !is AlarmScheduleResult.Scheduled) {
            return AlarmReconciliationResult.Failed(scheduleResult)
        }
        return AlarmReconciliationResult.Applied(desired, obsolete)
    }

    private fun stableRequestCode(fajrAt: ZonedDateTime, sequence: Int): Int {
        return Math.floorMod(
            (fajrAt.toLocalDate().toEpochDay() * 31L + sequence).toInt(),
            Int.MAX_VALUE
        )
    }
}

class PrayerAlarmRecoveryReceiver : BroadcastReceiver() {

    override fun onReceive(context: Context, intent: Intent) {
        val pendingResult = goAsync()
        val application = context.applicationContext as PrayerAlarmApplication
        CoroutineScope(Dispatchers.IO).launch {
            try {
                reconcile(application)
            } finally {
                pendingResult.finish()
            }
        }
    }

    private suspend fun reconcile(application: PrayerAlarmApplication) {
        val location = application.locationRepository.getActiveLocation().first()
        val config = application.alarmPlanPreferences.config.first()
        if (location == null) {
            NotificationHelper.cancel(application)
            return
        }

        val zone = runCatching { ZoneId.of(location.timeZoneId) }
            .getOrElse { ZoneId.of("Africa/Tunis") }
        val clock = Clock.systemUTC()
        val today = LocalDate.now(clock.withZone(zone))
        val todayTimetable = PrayerTimeCalculator.calculateTimetable(location, today)
        val tomorrowTimetable =
            PrayerTimeCalculator.calculateTimetable(location, today.plusDays(1))
        val days = listOf(todayTimetable, tomorrowTimetable).map { timetable ->
            FajrScheduleDay(timetable.prayerDateTimes[PrayerType.FAJR]!!)
        }
        val coordinator = PrayerAlarmCoordinator(application.prayerAlarmScheduler)
        val existing = candidateAlarms(days, config, location.name, coordinator)
        coordinator.reconcile(days, config, Instant.now(clock), existing)

        if (!config.enabled) {
            NotificationHelper.cancel(application)
            return
        }

        val now = Instant.now(clock)
        val countdown = PrayerTimeCalculator.computeNextPrayerAndCountdown(
            location = location,
            currentDate = today,
            now = now,
            todayTimetable = todayTimetable,
            tomorrowTimetable = tomorrowTimetable
        )
        val remainingMillis = countdown.nextPrayerDateTime
            ?.let { Duration.between(now, it).toMillis() }
            ?: 0L
        NotificationHelper.postWhenEnabled(
            context = application,
            selectedLocation = location,
            nextPrayer = countdown.nextPrayerItem,
            remainingMillis = remainingMillis
        )
        CountdownNotificationService.start(application)
    }

    private fun candidateAlarms(
        days: List<FajrScheduleDay>,
        config: AlarmPlanConfig,
        locationName: String,
        coordinator: PrayerAlarmCoordinator
    ): List<ScheduledPrayerAlarm> {
        val enabledConfig = config.copy(enabled = true)
        return days.flatMap { day ->
            val generated = AlarmPlanGenerator.generate(
                day.fajrAt.toLocalDateTime(),
                enabledConfig
            )
            (generated as? com.example.prayeralarm.domain.alarm.AlarmPlanResult.Success)
                ?.alarms
                ?.map { alarm ->
                    val instant = alarm.scheduledAt.atZone(day.fajrAt.zone).toInstant()
                    ScheduledPrayerAlarm(
                        requestCode = coordinator.requestCodeFor(day, alarm.sequence),
                        triggerAtMillis = instant.toEpochMilli(),
                        prayerName = "Fajr",
                        locationName = locationName
                    )
                }
                .orEmpty()
        }
    }

package com.example.prayeralarm.data.local

import com.example.prayeralarm.data.local.dao.LocationDao
import com.example.prayeralarm.data.preferences.LocationSelectionStore
import kotlinx.coroutines.flow.first

import kotlinx.coroutines.sync.withLock

/**
 * Outcome of a startup seed/selection repair pass.
 *
 * @property seeded True only when an empty database was populated with [DefaultLocations]
 * @property selectedLocationId The selection after the pass (null only if no rows exist)
 * @property repairedSelection True when an unset or dangling selection was replaced
 */
data class LocationSeedResult(
    val seeded: Boolean,
    val selectedLocationId: Long?,
    val repairedSelection: Boolean = false
)

/**
 * Seeds the three Tunisian defaults exactly once and repairs a broken selection.
 *
 * Upgrade safety:
 * - Existing rows are never deleted, updated, or re-inserted.
 * - Seeding runs only when the table is completely empty.
 * - A valid existing selection is preserved.
 * - Only an unset selection, or one pointing at a deleted row, is replaced.
 */
class LocationSeeder(
    private val locationDao: LocationDao,
    private val selectionStore: LocationSelectionStore
) {
    private val mutex = Mutex()

    suspend fun seedIfNeeded(): LocationSeedResult = mutex.withLock {
        if (locationDao.getLocationCount() == 0) {
            val insertedIds = locationDao.insertLocations(DefaultLocations.all)
            // insertLocations returns IDs in input order, so the first ID is Mahdia.
            val primaryId = insertedIds.firstOrNull()
                ?: locationDao.getAllLocations().first().firstOrNull()?.id
            if (primaryId != null) {
                selectionStore.setSelectedLocationId(primaryId)
            }
            return@withLock LocationSeedResult(
                seeded = true,
                selectedLocationId = primaryId
            )
        }

        repairSelectionIfNeeded()
    }

    private suspend fun repairSelectionIfNeeded(): LocationSeedResult {
        val selectedId = selectionStore.selectedLocationId.first()
        if (selectedId != null && locationDao.getLocationById(selectedId) != null) {
            return LocationSeedResult(
                seeded = false,
                selectedLocationId = selectedId
            )
        }

        // DAO orders by name, matching LocationRepositoryImpl's fallback.
        val fallback = locationDao.getAllLocations().first().firstOrNull()
            ?: return LocationSeedResult(seeded = false, selectedLocationId = null)

        selectionStore.setSelectedLocationId(fallback.id)
        return LocationSeedResult(
            seeded = false,
            selectedLocationId = fallback.id,
            repairedSelection = true
        )
    }
}

const val NOTIFICATION_ID_NEXT_PRAYER = 12345

/**
 * Handles posting, updating, and canceling the persistent "next prayer" notification.
 * A stable notification ID is reused so updates replace the existing notification
 * instead of creating duplicates.
 *
 * Integration points:
 * - [init] is called from [com.example.prayeralarm.PrayerAlarmApplication.onCreate]
 * - [postWhenEnabled] is called when the alarm plan is enabled and data is available
 * - [updateCountdown] may be called by the lifecycle-independent countdown service
 * - [cancel] is called when the alarm plan is disabled
 * - [postWhenEnabled] is also called from PrayerAlarmRecoveryReceiver after reboot/etc.
 */
object NotificationHelper {

    private const val CONTENT_INTENT_REQUEST_CODE = 1001

    @Volatile
    private var channelsCreated = false

    /** Must be called once during Application.onCreate. */
    fun init(context: Context) {
        ensureChannels(context)
    }

    /** Post the persistent notification when the alarm plan becomes enabled. */
    fun postWhenEnabled(
        context: Context,
        selectedLocation: SavedLocation,
        nextPrayer: PrayerScheduleItem?,
        remainingMillis: Long
    ) {
        if (!isNotificationEnabled(context)) return

        val appContext = context.applicationContext
        ensureChannels(appContext)

        if (nextPrayer == null) {
            cancel(appContext)
            return
        }

        manager(appContext).notify(
            NOTIFICATION_ID_NEXT_PRAYER,
            buildNotification(appContext, nextPrayer.type.displayName, nextPrayer.time.format(timeFormatter), remainingMillis)
        )
    }

    /** Update the notification content (replaces the existing notification). */
    fun updateCountdown(
        context: Context,
        nextPrayer: PrayerScheduleItem?,
        remainingMillis: Long,
        selectedLocation: SavedLocation
    ) {
        postWhenEnabled(context, selectedLocation, nextPrayer, remainingMillis)
    }

    /** Cancel the persistent notification. */
    fun cancel(context: Context) {
        manager(context.applicationContext).cancel(NOTIFICATION_ID_NEXT_PRAYER)
    }

    /**
     * Builds the same stable notification used by the foreground service for
     * both its initial foreground notification and subsequent updates.
     */
    fun buildNotification(
        context: Context,
        prayerName: String,
        prayerTime: String,
        remainingMillis: Long
    ): android.app.Notification {
        val appContext = context.applicationContext
        ensureChannels(appContext)
        val countdownText = formatCountdown(remainingMillis)
        val contentText = "$countdownText    $prayerTime"
        val compactView = notificationView(
            appContext,
            R.layout.notification_countdown,
            prayerName,
            countdownText,
            prayerTime
        )
        val expandedView = notificationView(
            appContext,
            R.layout.notification_countdown_expanded,
            prayerName,
            countdownText,
            prayerTime
        )

        return NotificationCompat.Builder(
            appContext,
            NotificationChannels.PRAYER_COUNTDOWN_CHANNEL
        ).apply {
            setSmallIcon(R.drawable.ic_notification)
            setColor(ContextCompat.getColor(appContext, R.color.notification_bg))
            setColorized(true)
            setContentTitle(prayerName)
            setContentText(contentText)
            setStyle(
                NotificationCompat.DecoratedCustomViewStyle()
            )
            setCustomContentView(compactView)
            setCustomBigContentView(expandedView)
            setContentIntent(openAppIntent(appContext))
            setPriority(NotificationCompat.PRIORITY_LOW)
            setCategory(NotificationCompat.CATEGORY_STATUS)
            setVisibility(NotificationCompat.VISIBILITY_PUBLIC)
            setShowWhen(false)
            setOnlyAlertOnce(true)
            setSilent(true)
            setOngoing(true)
            setAutoCancel(false)
        }.build()
    }

    private fun notificationView(
        context: Context,
        layoutId: Int,
        prayerName: String,
        countdownText: String,
        prayerTime: String
    ): RemoteViews {
        return RemoteViews(context.packageName, layoutId).apply {
            setTextViewText(R.id.notification_prayer_name, prayerName)
            setTextViewText(R.id.notification_countdown, countdownText)
            setTextViewText(R.id.notification_prayer_time, prayerTime)
        }
    }

    fun isNotificationEnabled(context: Context): Boolean {
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU &&
            ContextCompat.checkSelfPermission(
                context,
                Manifest.permission.POST_NOTIFICATIONS
            ) != PackageManager.PERMISSION_GRANTED
        ) {
            return false
        }
        return NotificationManagerCompat.from(context.applicationContext).areNotificationsEnabled()
    }

    private fun ensureChannels(context: Context) {
        if (channelsCreated) return
        NotificationChannels.create(context.applicationContext)
        channelsCreated = true
    }

    private fun manager(context: Context): NotificationManagerCompat {
        return NotificationManagerCompat.from(context.applicationContext)
    }

    private fun openAppIntent(context: Context): PendingIntent {
        val intent = Intent(context, MainActivity::class.java).apply {
            flags = Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_ACTIVITY_CLEAR_TOP
        }
        return PendingIntent.getActivity(
            context,
            CONTENT_INTENT_REQUEST_CODE,
            intent,
            PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE
        )
    }

    private fun formatCountdown(millis: Long): String {
        val totalSeconds = millis.coerceAtLeast(0L) / 1000L
        val hours = totalSeconds / 3600L
        val minutes = (totalSeconds % 3600L) / 60L
        val seconds = totalSeconds % 60L
        return if (hours > 0L) {
            String.format(Locale.US, "%02d:%02d:%02d", hours, minutes, seconds)
        } else {
            String.format(Locale.US, "%02d:%02d", minutes, seconds)
        }
    }

    private val timeFormatter: DateTimeFormatter = DateTimeFormatter.ofPattern("HH:mm")

/**
 * Concrete implementation of [LocationRepository] coordinating Room database and DataStore preferences.
 */
class LocationRepositoryImpl(
    private val locationDao: LocationDao,
    private val selectionStore: LocationSelectionStore
) : LocationRepository {

    override fun getAllLocations(): Flow<List<SavedLocation>> {
        return combine(
            locationDao.getAllLocations(),
            selectionStore.selectedLocationId
        ) { entities, selectedId ->
            entities.map { entity ->
                entity.toDomain(isSelected = (entity.id == selectedId))
            }
        }
    }

    override fun getActiveLocation(): Flow<SavedLocation?> {
        return combine(
            locationDao.getAllLocations(),
            selectionStore.selectedLocationId
        ) { entities, selectedId ->
            if (entities.isEmpty()) {
                null
            } else {
                // Return explicitly selected location or default to first location in list
                val activeEntity = entities.find { it.id == selectedId } ?: entities.first()
                activeEntity.toDomain(isSelected = true)
            }
        }
    }

    override suspend fun getLocationById(id: Long): SavedLocation? {
        return locationDao.getLocationById(id)?.toDomain()
    }

    override suspend fun addLocation(location: SavedLocation): Long {
        val existing = locationDao.findByIdentity(
            name = location.name,
            latitude = location.latitude,
            longitude = location.longitude,
            timeZoneId = location.timeZoneId
        )
        if (existing != null) {
            if (location.isDefault) {
                selectionStore.setSelectedLocationId(existing.id)
            }
            return existing.id
        }

        val entity = location.toEntity()
        val newId = locationDao.insertLocation(entity)
        // If this is set as default or is the first inserted location, set as active
        if (location.isDefault) {
            selectionStore.setSelectedLocationId(newId)
        }
        return newId
    }

    override suspend fun updateLocation(location: SavedLocation): Boolean {
        val rows = locationDao.updateLocation(location.toEntity())
        return rows > 0
    }

    override suspend fun deleteLocation(location: SavedLocation): Boolean {
        val selectedId = selectionStore.selectedLocationId.first()
        val rows = locationDao.deleteLocationById(location.id)
        if (rows > 0 && selectedId == location.id) {
            val replacement = locationDao.getAllLocations().first().firstOrNull()
            if (replacement == null) {
                selectionStore.clearSelectedLocationId()
            } else {
                selectionStore.setSelectedLocationId(replacement.id)
            }
        }
        return rows > 0
    }

    override suspend fun setActiveLocation(locationId: Long) {
        selectionStore.setSelectedLocationId(locationId)
    }

package com.example.prayeralarm.domain.alarm

import java.time.LocalDateTime
import java.time.temporal.ChronoUnit

enum class AlarmTimingMode {
    BEFORE_FAJR,
    AT_OR_AFTER_FAJR,
    BOTH
}

data class AlarmPlanConfig(
    val alarmCount: Int,
    val intervalMinutes: Long,
    val timingMode: AlarmTimingMode,
    val enabled: Boolean = true
) {
    companion object {
        val DEFAULT = AlarmPlanConfig(
            alarmCount = 5,
            intervalMinutes = 10L,
            timingMode = AlarmTimingMode.BOTH,
            enabled = false
        )
    }
}

data class PlannedAlarm(
    val sequence: Int,
    val scheduledAt: LocalDateTime
)

sealed interface AlarmPlanResult {
    data class Success(val alarms: List<PlannedAlarm>) : AlarmPlanResult
    data class Invalid(val message: String) : AlarmPlanResult
}

object AlarmPlanGenerator {

    fun generate(
        fajrAt: LocalDateTime,
        config: AlarmPlanConfig
    ): AlarmPlanResult {
        if (!config.enabled) {
            return AlarmPlanResult.Success(emptyList())
        }
        if (config.alarmCount < 1) {
            return AlarmPlanResult.Invalid("Alarm count must be at least one.")
        }
        if (config.intervalMinutes < 1) {
            return AlarmPlanResult.Invalid("Alarm interval must be at least one minute.")
        }

        val timestamps = when (config.timingMode) {
            AlarmTimingMode.BEFORE_FAJR -> {
                (config.alarmCount - 1 downTo 0).map { offset ->
                    fajrAt.minusMinutes(offset * config.intervalMinutes)
                }
            }

            AlarmTimingMode.AT_OR_AFTER_FAJR -> {
                (0 until config.alarmCount).map { offset ->
                    fajrAt.plusMinutes(offset * config.intervalMinutes)
                }
            }

            AlarmTimingMode.BOTH -> {
                (config.alarmCount - 1 downTo 0).map { offset ->
                    fajrAt.minusMinutes(offset * config.intervalMinutes)
                }
            }
        }.distinct()

        if (timestamps.size != config.alarmCount) {
            return AlarmPlanResult.Invalid("Alarm configuration produced duplicate timestamps.")
        }

        return AlarmPlanResult.Success(
            timestamps.mapIndexed { index, timestamp ->
                PlannedAlarm(sequence = index + 1, scheduledAt = timestamp)
            }
        )
    }

    fun durationBetweenFirstAndLast(alarms: List<PlannedAlarm>): Long {
        if (alarms.size < 2) return 0L
        return ChronoUnit.MINUTES.between(alarms.first().scheduledAt, alarms.last().scheduledAt)
    }
}

        fajrAngle = 18.0,
        ishaAngle = 18.0,
        madhab = Madhab.SHAFI,
        summary = "Fajr 18°, Isha 18°, Shafi'i/Maliki standard Asr shadow factor"

     * @param method Named calculation convention (defaults to [PrayerCalculationMethod.DEFAULT])
     * @return CalculatedTimetable containing prayer rows, exact ZonedDateTimes, sunrise, and metadata
     */
    fun calculateTimetable(
        location: SavedLocation,
        date: LocalDate,
        method: PrayerCalculationMethod = PrayerCalculationMethod.DEFAULT
    ): CalculatedTimetable {
        val zoneId = zoneIdFor(location)

        val coordinates = Coordinates(location.latitude, location.longitude)
        val dateComponents = DateComponents(date.year, date.monthValue, date.dayOfMonth)

        val adhanPrayerTimes = com.batoulapps.adhan.PrayerTimes(
            coordinates,
            dateComponents,
            method.createParameters()
        )

        fun dateToZonedDateTime(dateObj: Date?): ZonedDateTime {
            return if (dateObj != null) {
                dateObj.toInstant().atZone(zoneId)
            } else {
                // Fallback to approximate noon if an extreme-latitude event is undefined.
                date.atTime(12, 0).atZone(zoneId)
            }
        }

        val fajrZdt = dateToZonedDateTime(adhanPrayerTimes.fajr)
        val sunriseZdt = dateToZonedDateTime(adhanPrayerTimes.sunrise)
        val dhuhrZdt = dateToZonedDateTime(adhanPrayerTimes.dhuhr)
        val asrZdt = dateToZonedDateTime(adhanPrayerTimes.asr)
        val maghribZdt = dateToZonedDateTime(adhanPrayerTimes.maghrib)
        val ishaZdt = dateToZonedDateTime(adhanPrayerTimes.isha)

        val prayerMap = mapOf(
            PrayerType.FAJR to fajrZdt,
            PrayerType.DHUHR to dhuhrZdt,
            PrayerType.ASR to asrZdt,
            PrayerType.MAGHRIB to maghribZdt,
            PrayerType.ISHA to ishaZdt
        )

        val items = listOf(
            PrayerScheduleItem(type = PrayerType.FAJR, time = fajrZdt.toLocalTime()),
            PrayerScheduleItem(type = PrayerType.DHUHR, time = dhuhrZdt.toLocalTime()),
            PrayerScheduleItem(type = PrayerType.ASR, time = asrZdt.toLocalTime()),
            PrayerScheduleItem(type = PrayerType.MAGHRIB, time = maghribZdt.toLocalTime()),
            PrayerScheduleItem(type = PrayerType.ISHA, time = ishaZdt.toLocalTime())
        )

        return CalculatedTimetable(
            date = date,
            items = items,
            prayerDateTimes = prayerMap,
            sunrise = sunriseZdt,
            locationZoneId = zoneId,
            calculationMethod = method
        )
    }

    /**
     * Determines the next upcoming prayer and computes the exact remaining countdown duration.
     *
     * Source of truth is the difference between [now] and the target prayer's [ZonedDateTime].
     * If all prayers for [currentDate] have passed, automatically calculates tomorrow's Fajr
     * so the countdown seamlessly points to tomorrow morning's dawn prayer.
     *
     * @param location The active SavedLocation
     * @param currentDate The current calendar date in the location's timezone
     * @param now The current instant
     * @param todayTimetable The calculated timetable for today
     * @return NextPrayerCountdown with highlighted item, target timestamp, and remaining H:M:S
     */
    fun computeNextPrayerAndCountdown(
        location: SavedLocation,
        currentDate: LocalDate,
        now: Instant,
        todayTimetable: CalculatedTimetable,
        tomorrowTimetable: CalculatedTimetable? = null
    ): NextPrayerCountdown {
        // Ordered list of today's prayers
        val prayersToday = listOf(
            Pair(PrayerType.FAJR, todayTimetable.prayerDateTimes[PrayerType.FAJR]!!),
            Pair(PrayerType.DHUHR, todayTimetable.prayerDateTimes[PrayerType.DHUHR]!!),
            Pair(PrayerType.ASR, todayTimetable.prayerDateTimes[PrayerType.ASR]!!),
            Pair(PrayerType.MAGHRIB, todayTimetable.prayerDateTimes[PrayerType.MAGHRIB]!!),
            Pair(PrayerType.ISHA, todayTimetable.prayerDateTimes[PrayerType.ISHA]!!)
        )

        // Find the first prayer strictly in the future relative to 'now'
        val upcoming = prayersToday.firstOrNull { (_, zdt) ->
            zdt.toInstant().isAfter(now)
        }

        val targetPrayerType: PrayerType
        val targetZdt: ZonedDateTime
        val isTomorrowFajr: Boolean

        if (upcoming != null) {
            targetPrayerType = upcoming.first
            targetZdt = upcoming.second
            isTomorrowFajr = false
        } else {
            // All prayers for today have passed. Next prayer is tomorrow's Fajr!
            val tomorrow = currentDate.plusDays(1)
            val nextDayTimetable = tomorrowTimetable ?: calculateTimetable(location, tomorrow)
            targetPrayerType = PrayerType.FAJR
            targetZdt = nextDayTimetable.prayerDateTimes[PrayerType.FAJR]!!
            isTomorrowFajr = true
        }

        // Compute exact non-negative remaining seconds
        val targetInstant = targetZdt.toInstant()
        val totalSecondsRemaining = if (targetInstant.isAfter(now)) {
            java.time.Duration.between(now, targetInstant).seconds
        } else {
            0L
        }

        val hours = totalSecondsRemaining / 3600
        val minutes = (totalSecondsRemaining % 3600) / 60
        val seconds = totalSecondsRemaining % 60

        // Item shown by the "next prayer" card/notification.
        //
        // After Isha the target is tomorrow's Fajr. That timestamp must NOT be
        // written into today's Fajr row: today's timetable is historical data and
        // the UI highlights rows by PrayerType. Callers therefore keep the today
        // rows untouched and show this standalone item only in the next-prayer card.
        val highlightedItem = if (!isTomorrowFajr) {
            todayTimetable.items.find { it.type == targetPrayerType }?.copy(isNextPrayer = true)
        } else {
            PrayerScheduleItem(
                type = PrayerType.FAJR,
                time = targetZdt.toLocalTime(),
                isNextPrayer = true
            )
        }

        return NextPrayerCountdown(
            nextPrayerItem = highlightedItem,
            nextPrayerDateTime = targetZdt,
            remainingHours = hours,
            remainingMinutes = minutes,
            remainingSeconds = seconds,
            isPastAllPrayersForDay = isTomorrowFajr
        )
    }
}

import kotlinx.coroutines.flow.MutableStateFlow

import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.catch
import kotlinx.coroutines.launch

class AlarmPlanViewModel(
    private val preferences: AlarmPlanPreferences
) : ViewModel() {

    private val _config = MutableStateFlow(AlarmPlanConfig.DEFAULT)
    val config: StateFlow<AlarmPlanConfig> = _config.asStateFlow()

    private val _errorMessage = MutableStateFlow<String?>(null)
    val errorMessage: StateFlow<String?> = _errorMessage.asStateFlow()

    init {
        viewModelScope.launch {
            preferences.config
                .catch { error -> _errorMessage.value = error.message ?: "Unable to load alarm settings." }
                .collect { _config.value = it }
        }
    }

    fun setEnabled(enabled: Boolean) = update { it.copy(enabled = enabled) }

    fun setAlarmCount(count: Int) = update { it.copy(alarmCount = count) }

    fun setIntervalMinutes(interval: Long) = update { it.copy(intervalMinutes = interval) }

    fun setTimingMode(mode: AlarmTimingMode) = update { it.copy(timingMode = mode) }

    private fun update(transform: (AlarmPlanConfig) -> AlarmPlanConfig) {
        val updated = transform(_config.value)
        if (updated.alarmCount < 1 || updated.intervalMinutes < 1) {
            _errorMessage.value = "Alarm count and interval must be positive."
            return
        }
        _errorMessage.value = null
        _config.value = updated
        viewModelScope.launch {
            runCatching { preferences.setConfig(updated) }
                .onFailure { _errorMessage.value = it.message ?: "Unable to save alarm settings." }
        }
    }

    class Factory(private val preferences: AlarmPlanPreferences) : ViewModelProvider.Factory {
        @Suppress("UNCHECKED_CAST")
        override fun <T : ViewModel> create(modelClass: Class<T>): T {
            if (modelClass.isAssignableFrom(AlarmPlanViewModel::class.java)) {
                return AlarmPlanViewModel(preferences) as T
            }
            throw IllegalArgumentException("Unknown ViewModel class")
        }
    }
}

/**
 * ViewModel managing Home Screen prayer timetable and real-time countdown.
 *
 * Implements real astronomical calculation based on the active [SavedLocation].
 * Uses an injectable [Clock] for deterministic testing.
 */
class HomeViewModel(
    private val locationRepository: LocationRepository? = null,
    private val clock: Clock = Clock.systemUTC(),
    private val alarmPlanPreferences: AlarmPlanPreferences? = null,
    private val notificationContext: Context? = null
) : ViewModel() {

    private val _uiState = MutableStateFlow(HomeUiState(isLoading = true))
    val uiState: StateFlow<HomeUiState> = _uiState.asStateFlow()

    private var activeLocation: SavedLocation? = null
    private var cachedTimetable: CalculatedTimetable? = null
    private var cachedTimetableDate: LocalDate? = null
    private var cachedTomorrowTimetable: CalculatedTimetable? = null
    private var persistentNotificationEnabled = false

    init {
        observeActiveLocation()
        observeNotificationPlan()
        startCountdownTicker()
    }

    /**
     * Keeps the persistent notification in sync with the persisted alarm-plan toggle.
     * Disabling the plan cancels the notification immediately.
     */
    private fun observeNotificationPlan() {
        val preferences = alarmPlanPreferences ?: return
        viewModelScope.launch {
            preferences.config.collect { config ->
                persistentNotificationEnabled = config.enabled
                        if (!config.enabled) {
                            notificationContext?.let { CountdownNotificationService.stop(it) }
                        }
            }
        }
    }

    private fun observeActiveLocation() {
        locationRepository?.let { repo ->
            viewModelScope.launch {
                repo.getActiveLocation().collect { location ->
                    if (location != null) {
                        activeLocation = location
                        recalculateTimetable(location)
                    } else {
                        _uiState.update { current ->
                            current.copy(
                                isLoading = false,
                                errorMessage = "No active location available."
                            )
                        }
                    }
                }
            }
        }
    }

    /**
     * Recalculates prayer times for the provided location and updates the countdown.
     * Avoids recalculating table values on every countdown tick by caching the day's timetable.
     */
    private fun recalculateTimetable(location: SavedLocation) {
        val zoneId = PrayerTimeCalculator.zoneIdFor(location)

        val today = LocalDate.now(clock.withZone(zoneId))
        val timetable = PrayerTimeCalculator.calculateTimetable(location, today)
        cachedTimetable = timetable
        cachedTimetableDate = today
        cachedTomorrowTimetable = PrayerTimeCalculator.calculateTimetable(location, today.plusDays(1))

        val now = Instant.now(clock)
        val countdown = PrayerTimeCalculator.computeNextPrayerAndCountdown(
            location = location,
            currentDate = today,
            now = now,
            todayTimetable = timetable,
            tomorrowTimetable = cachedTomorrowTimetable
        )

        val updatedItems = applyNextPrayerHighlight(timetable.items, countdown)

        _uiState.update { current ->
            current.copy(
                selectedLocation = location,
                currentDate = today,
                prayerTimetable = updatedItems,
                nextPrayer = countdown.nextPrayerItem,
                remainingHours = countdown.remainingHours,
                remainingMinutes = countdown.remainingMinutes,
                remainingSeconds = countdown.remainingSeconds,
                isSampleData = false,
                isLoading = false,
                errorMessage = null
            )
        }
    }

    /**
     * Marks at most one row in today's timetable as the next prayer.
     *
     * After Isha the countdown targets tomorrow's Fajr. Tomorrow's time is shown
     * in the next-prayer card only; no row in today's list is marked as "next"
     * because none of today's rows represents that upcoming prayer.
     */
    private fun applyNextPrayerHighlight(
        items: List<PrayerScheduleItem>,
        countdown: NextPrayerCountdown
    ): List<PrayerScheduleItem> {
        val nextTodayType = if (countdown.isPastAllPrayersForDay) {
            null
        } else {
            countdown.nextPrayerItem?.type
        }
        return items.map { item -> item.copy(isNextPrayer = item.type == nextTodayType) }
    }

    /**
     * Precise ticker running once per second.
     * Only updates the countdown and next-prayer pointer against pre-calculated timestamps.
     * If midnight passes (date changes), triggers a full timetable recalculation.
     */
    private fun startCountdownTicker() {
        viewModelScope.launch {
            while (isActive) {
                delay(1000L)
                tickCountdown()
            }
        }
    }

    /**
     * Advances the countdown by comparing the current instant with the upcoming prayer's timestamp.
     */
    fun tickCountdown() {
        val location = activeLocation ?: return
        val timetable = cachedTimetable ?: return
        val timetableDate = cachedTimetableDate ?: return

        val zoneId = PrayerTimeCalculator.zoneIdFor(location)

        val currentDate = LocalDate.now(clock.withZone(zoneId))

        // If the day has rolled over at midnight, recalculate today's timetable!
        if (currentDate != timetableDate) {
            recalculateTimetable(location)
            return
        }

        val now = Instant.now(clock)
        val countdown = PrayerTimeCalculator.computeNextPrayerAndCountdown(
            location = location,
            currentDate = currentDate,
            now = now,
            todayTimetable = timetable,
            tomorrowTimetable = cachedTomorrowTimetable
        )

        val updatedItems = applyNextPrayerHighlight(timetable.items, countdown)

        _uiState.update { current ->
            current.copy(
                nextPrayer = countdown.nextPrayerItem,
                prayerTimetable = updatedItems,
                remainingHours = countdown.remainingHours,
                remainingMinutes = countdown.remainingMinutes,
                remainingSeconds = countdown.remainingSeconds
            )
        }
    }

    fun togglePrayerNotification(prayerType: PrayerType) {
        _uiState.update { state ->
            val updated = state.prayerTimetable.map { item ->
                if (item.type == prayerType) {
                    item.copy(isNotificationEnabled = !item.isNotificationEnabled)
                } else {
                    item
                }
            }
            state.copy(prayerTimetable = updated)
        }
    }

    class Factory(
        private val repository: LocationRepository,
        private val clock: Clock = Clock.systemUTC(),
        private val alarmPlanPreferences: AlarmPlanPreferences? = null,
        private val notificationContext: Context? = null
    ) : ViewModelProvider.Factory {
        @Suppress("UNCHECKED_CAST")
        override fun <T : ViewModel> create(modelClass: Class<T>): T {
            if (modelClass.isAssignableFrom(HomeViewModel::class.java)) {
                return HomeViewModel(
                    repository,
                    clock,
                    alarmPlanPreferences,
                    notificationContext
                ) as T
            }
            throw IllegalArgumentException("Unknown ViewModel class")
        }
    }

    companion object {
        /**
         * Sample state strictly for Compose @Preview rendering in IDE.
         */
        fun createPreviewState(): HomeUiState {
            val sampleLocation = SavedLocation(
                id = 1,
                name = "Mahdia (Preview)",
                latitude = 35.5047,
                longitude = 11.0622,
                timeZoneId = "Africa/Tunis",
                isDefault = true
            )
            val timetable = PrayerTimeCalculator.calculateTimetable(sampleLocation, LocalDate.now())
            return HomeUiState(
                selectedLocation = sampleLocation,
                currentDate = LocalDate.now(),
                hijriDate = "18 Jumada al-Awwal 1448",
                nextPrayer = timetable.items[1],
                remainingHours = 2,
                remainingMinutes = 15,
                remainingSeconds = 30,
                prayerTimetable = timetable.items,
                isSampleData = true
            )
        }
    }

/** Fraction of the gap between the previous prayer and the next one that has already passed. */
private fun elapsedFraction(
    next: PrayerScheduleItem?,
    timetable: List<PrayerScheduleItem>,
    remainingSeconds: Long
): Float {
    if (next == null || timetable.isEmpty()) return 0f
    val idx = timetable.indexOfFirst { it.type == next.type }
    val prev = if (idx > 0) timetable[idx - 1] else timetable.last()
    var span = Duration.between(prev.time, next.time).seconds
    if (span <= 0) span += 86_400
    return (1f - remainingSeconds.toFloat() / span).coerceIn(0f, 1f)
}

package com.example.prayeralarm.ui.locations

import androidx.lifecycle.ViewModel
import androidx.lifecycle.ViewModelProvider
import androidx.lifecycle.viewModelScope
import com.example.prayeralarm.data.repository.LocationRepository
import com.example.prayeralarm.domain.model.SavedLocation
import com.example.prayeralarm.util.LocationValidator
import com.example.prayeralarm.util.ValidationResult
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.combine
import kotlinx.coroutines.flow.update
import kotlinx.coroutines.launch

/**
 * ViewModel managing location list presentation, editing, deletion with confirmation,
 * coordinate validation, and active selection.
 */
class LocationsViewModel(
    private val repository: LocationRepository
) : ViewModel() {

    private val _uiState = MutableStateFlow(LocationsUiState(isLoading = true))
    val uiState: StateFlow<LocationsUiState> = _uiState.asStateFlow()

    init {
        observeLocations()
    }

    private fun observeLocations() {
        viewModelScope.launch {
            combine(
                repository.getAllLocations(),
                repository.getActiveLocation()
            ) { locations, active ->
                Pair(locations, active)
            }.collect { (locations, active) ->
                _uiState.update { current ->
                    current.copy(
                        locations = locations,
                        activeLocation = active,
                        isLoading = false
                    )
                }
            }
        }
    }

    fun selectLocation(location: SavedLocation) {
        viewModelScope.launch {
            repository.setActiveLocation(location.id)
        }
    }

    fun openAddDialog() {
        _uiState.update { it.copy(showAddEditDialog = true, editingLocation = null) }
    }

    fun openEditDialog(location: SavedLocation) {
        _uiState.update { it.copy(showAddEditDialog = true, editingLocation = location) }
    }

    fun dismissAddEditDialog() {
        _uiState.update { it.copy(showAddEditDialog = false, editingLocation = null) }
    }

    fun saveLocation(
        name: String,
        latitudeStr: String,
        longitudeStr: String,
        timeZoneId: String
    ): ValidationResult {
        val validation = LocationValidator.validate(
            name = name,
            latitudeStr = latitudeStr,
            longitudeStr = longitudeStr,
            timezoneId = timeZoneId
        )

        if (!validation.isValid) {
            return validation
        }

        val lat = latitudeStr.trim().toDouble()
        val lon = longitudeStr.trim().toDouble()
        val tz = timeZoneId.trim()
        val locName = name.trim()

        viewModelScope.launch {
            val currentEditing = _uiState.value.editingLocation
            if (currentEditing != null) {
                // Update
                val updated = currentEditing.copy(
                    name = locName,
                    latitude = lat,
                    longitude = lon,
                    timeZoneId = tz
                )
                repository.updateLocation(updated)
            } else {
                // Add
                val isFirst = _uiState.value.locations.isEmpty()
                val newLocation = SavedLocation(
                    name = locName,
                    latitude = lat,
                    longitude = lon,
                    timeZoneId = tz,
                    isDefault = isFirst
                )
                repository.addLocation(newLocation)
            }
            dismissAddEditDialog()
        }

        return validation
    }

    fun requestDeleteLocation(location: SavedLocation) {
        _uiState.update { it.copy(locationToDelete = location) }
    }

    fun cancelDeleteLocation() {
        _uiState.update { it.copy(locationToDelete = null) }
    }

    fun confirmDeleteLocation() {
        val location = _uiState.value.locationToDelete ?: return
        viewModelScope.launch {
            repository.deleteLocation(location)
            _uiState.update { it.copy(locationToDelete = null) }
        }
    }

    class Factory(private val repository: LocationRepository) : ViewModelProvider.Factory {
        @Suppress("UNCHECKED_CAST")
        override fun <T : ViewModel> create(modelClass: Class<T>): T {
            if (modelClass.isAssignableFrom(LocationsViewModel::class.java)) {
                return LocationsViewModel(repository) as T
            }
            throw IllegalArgumentException("Unknown ViewModel class")
        }
    }
}

@Composable
fun MainScreen() {
    val context = LocalContext.current.applicationContext as PrayerAlarmApplication
    val locationRepository = context.locationRepository

    val homeViewModel: HomeViewModel = viewModel(
        factory = HomeViewModel.Factory(
            repository = locationRepository,
            alarmPlanPreferences = context.alarmPlanPreferences,
            notificationContext = context.applicationContext
        )
    )
    val locationsViewModel: LocationsViewModel = viewModel(
        factory = LocationsViewModel.Factory(locationRepository)
    )
    val alarmPlanViewModel: AlarmPlanViewModel = viewModel(
        factory = AlarmPlanViewModel.Factory(context.alarmPlanPreferences)
    )
    val settingsViewModel: SettingsViewModel = viewModel(
        factory = SettingsViewModel.Factory(locationRepository, context.preferencesManager)
    )
    viewModel<PrayerAlarmSchedulingViewModel>(
        factory = PrayerAlarmSchedulingViewModel.Factory(
            locationRepository = locationRepository,
            alarmPreferences = context.alarmPlanPreferences,
            scheduler = context.prayerAlarmScheduler
        )
    )

    // The on/off switch now lives in Settings, so the persistent countdown notification
    // is started/stopped here, where it is always active.
    val alarmConfig by alarmPlanViewModel.config.collectAsState()
    LaunchedEffect(alarmConfig.enabled) {
        if (alarmConfig.enabled) {
            CountdownNotificationService.start(context)
        } else {
            CountdownNotificationService.stop(context)
        }
    }

    val navController = rememberNavController()
    val navBackStackEntry by navController.currentBackStackEntryAsState()
    val currentRoute = navBackStackEntry?.destination?.route

    fun navigateToTopLevel(route: String) {
        if (currentRoute != route) {
            navController.navigate(route) {
                popUpTo(navController.graph.findStartDestination().id) {
                    saveState = true
                }
                launchSingleTop = true
                restoreState = true
            }
        }
    }

    val screens = listOf(
        Screen.Home,
        Screen.Alarms,
        Screen.Settings
    )

    Scaffold(
        containerColor = NavyDark,
        bottomBar = {
            FloatingBottomBar(
                screens = screens,
                // Locations is opened from Settings, so keep the Settings tab lit there.
                selectedRoute = if (currentRoute == Screen.Locations.route) Screen.Settings.route else currentRoute,
                onSelect = { navigateToTopLevel(it.route) }
            )
        }
    ) { innerPadding ->
        NavHost(
            navController = navController,
            startDestination = Screen.Home.route,
            modifier = Modifier.padding(innerPadding)
        ) {
            composable(Screen.Home.route) {
                val uiState by homeViewModel.uiState.collectAsState()
                HomeScreen(
                    uiState = uiState,
                    onToggleNotification = { prayerType ->
                        homeViewModel.togglePrayerNotification(prayerType)
                    }
                )
            }

            composable(Screen.Locations.route) {
                val locationsUiState by locationsViewModel.uiState.collectAsState()
                LocationsScreen(
                    uiState = locationsUiState,
                    onSelectLocation = { location ->
                        locationsViewModel.selectLocation(location)
                    },
                    onOpenAddDialog = {
                        locationsViewModel.openAddDialog()
                    },
                    onOpenEditDialog = { location ->
                        locationsViewModel.openEditDialog(location)
                    },
                    onDismissDialog = {
                        locationsViewModel.dismissAddEditDialog()
                    },
                    onSaveLocation = { name, lat, lon, tz ->
                        locationsViewModel.saveLocation(name, lat, lon, tz)
                    },
                    onRequestDelete = { location ->
                        locationsViewModel.requestDeleteLocation(location)
                    },
                    onCancelDelete = {
                        locationsViewModel.cancelDeleteLocation()
                    },
                    onConfirmDelete = {
                        locationsViewModel.confirmDeleteLocation()
                    }
                )
            }

            composable(Screen.Alarms.route) {
                val uiState by homeViewModel.uiState.collectAsState()
                AlarmPlanScreen(homeUiState = uiState, viewModel = alarmPlanViewModel)
            }

            composable(Screen.Settings.route) {
                SettingsScreen(
                    viewModel = settingsViewModel,
                    alarmPlanViewModel = alarmPlanViewModel,
                    onLocationChange = { navigateToTopLevel(Screen.Locations.route) }
                )
            }
        }
    }
}

    selectedRoute: String?,

        modifier = Modifier
            .navigationBarsPadding()
            .padding(horizontal = 20.dp, vertical = 12.dp)

            .clip(shape)
            .background(NavyBar)
            .border(1.dp, NavyBorder, shape)
            .padding(6.dp),
        horizontalArrangement = Arrangement.spacedBy(4.dp)
    ) {
        screens.forEach { screen ->
            BarItem(
                screen = screen,
                selected = screen.route == selectedRoute,
                onClick = { onSelect(screen) }
            )
        }
    }

import androidx.lifecycle.ViewModel

import kotlinx.coroutines.flow.Flow

import kotlinx.coroutines.launch

/**
 * ViewModel for the Settings screen.
 *
 * Exposes the currently selected location and the prayer-time calculation convention.
 * Persists user changes to calculation settings.
 */
class SettingsViewModel(
    private val locationRepository: LocationRepository,
    private val preferencesManager: UserPreferencesManager? = null
) : ViewModel() {

    /** The currently selected active location, or null when none is available. */
    val selectedLocation: Flow<SavedLocation?> = locationRepository.getActiveLocation()

    /** The named prayer-time calculation convention used by the app. */
    val calculationMethod: Flow<PrayerCalculationMethod> =
        preferencesManager?.calculationMethod ?: flowOf(PrayerCalculationMethod.DEFAULT)

    fun setCalculationMethod(method: PrayerCalculationMethod) {
        preferencesManager?.let { prefs ->
            viewModelScope.launch {
                prefs.setCalculationMethod(method)
            }
        }
    }

    class Factory(
        private val locationRepository: LocationRepository,
        private val preferencesManager: UserPreferencesManager? = null
    ) : ViewModelProvider.Factory {
        @Suppress("UNCHECKED_CAST")
        override fun <T : ViewModel> create(modelClass: Class<T>): T {
            if (modelClass.isAssignableFrom(SettingsViewModel::class.java)) {
                return SettingsViewModel(locationRepository, preferencesManager) as T
            }
            throw IllegalArgumentException("Unknown ViewModel class")
        }
    }
}

    val longitudeError: String? = null,
    val timezoneError: String? = null
)

/**
 * Validates coordinate inputs, name, and IANA timezone ID.
 */
object LocationValidator {

    private const val MIN_LATITUDE = -90.0
    private const val MAX_LATITUDE = 90.0
    private const val MIN_LONGITUDE = -180.0
    private const val MAX_LONGITUDE = 180.0

    /**
     * Comprehensive validation of all location fields.
     */
    fun validate(
        name: String,
        latitudeStr: String,
        longitudeStr: String,
        timezoneId: String
    ): ValidationResult {
        val nameError = validateName(name)
        val latError = validateLatitude(latitudeStr)
        val lonError = validateLongitude(longitudeStr)
        val tzError = validateTimezoneId(timezoneId)

        val isValid = nameError == null && latError == null && lonError == null && tzError == null
        return ValidationResult(
            isValid = isValid,
            nameError = nameError,
            latitudeError = latError,
            longitudeError = lonError,
            timezoneError = tzError
        )
    }

    fun validateName(name: String): String? {
        val trimmed = name.trim()
        return when {
            trimmed.isEmpty() -> "Location name cannot be empty"
            trimmed.length < 2 -> "Name must be at least 2 characters"
            trimmed.length > 50 -> "Name must not exceed 50 characters"
            else -> null
        }
    }

    fun validateLatitude(latitudeStr: String): String? {
        val trimmed = latitudeStr.trim()
        if (trimmed.isEmpty()) return "Latitude is required"
        val lat = trimmed.toDoubleOrNull() ?: return "Latitude must be a valid decimal number"
        if (!lat.isFinite()) return "Latitude must be a finite decimal number"
        return if (lat in MIN_LATITUDE..MAX_LATITUDE) {
            null
        } else {
            "Latitude must be between -90.0 and +90.0"
        }
    }

    fun validateLongitude(longitudeStr: String): String? {
        val trimmed = longitudeStr.trim()
        if (trimmed.isEmpty()) return "Longitude is required"
        val lon = trimmed.toDoubleOrNull() ?: return "Longitude must be a valid decimal number"
        if (!lon.isFinite()) return "Longitude must be a finite decimal number"
        return if (lon in MIN_LONGITUDE..MAX_LONGITUDE) {
            null
        } else {
            "Longitude must be between -180.0 and +180.0"
        }
    }

    /**
     * Accepts only canonical IANA region/alias IDs that java.time knows about.
     *
     * Offset-style IDs such as `+01:00`, `Z`, or `UTC+01:00` are deliberately
     * rejected: they cannot describe historical DST rules, so they would make
     * prayer times drift whenever the zone's offset changes.
     */
    fun validateTimezoneId(timezoneId: String): String? {
        val trimmed = timezoneId.trim()
        if (trimmed.isEmpty()) return "Timezone ID is required"
        return if (ZoneId.getAvailableZoneIds().contains(trimmed)) {
            null
        } else {
            "Invalid IANA timezone ID (e.g., Africa/Tunis, Europe/London)"
        }
    }
}
